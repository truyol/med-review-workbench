# 真实医疗软件场景能力差距与边界

状态：P3 退出前确认  
更新时间：2026-09-20

## 目的

本项目是工程能力验证原型，不是医疗器械、临床阅片器或医院生产系统。本文件明确说明：MVP 为了证明面试题核心闭环做什么，以及真实医疗软件上线前还必须补什么。这里的说明不代表已完成法规认证或生产安全评审。

## MVP 与生产能力对照

| 领域 | 本次 MVP | 真实医疗软件必须补充 | 验证/治理重点 |
|---|---|---|---|
| 身份认证 | 不接真实账号，使用演示角色 | 对接组织身份源、MFA、会话超时、账号生命周期 | 未认证访问、离职账号、会话劫持 |
| 权限 | 文档化 `planner_engineer`、`technical_reviewer`、`viewer` | 按组织/项目/病例实施最小权限 RBAC/ABAC，服务端逐项授权 | 越权读取、水平越权、批量导出 |
| 审计 | 只有追加式评审历史与带 `request_id` 的运行日志；`actor` 与 `audit_events` 仅为未来设计，当前无对应表/字段 | 追加式审计：主体、时间、对象、动作、结果、修改前后摘要、来源 IP/设备、request_id；防篡改与留存策略 | 审计完整性、检索、导出与告警 |
| 隐私 | 公开/合成/本地清理样例；DICOM 白名单展示；敏感字段不进日志 | 数据分级、最少必要、用途与授权管理、传输/静态加密、密钥管理、删除与留存、备份恢复 | 日志扫描、导出控制、数据生命周期 |
| DICOM 去标识化 | demo 脚本清理直接身份标签和私有标签，不宣称临床级匿名化 | 按适用标准建立去标识化配置、UID/日期一致性策略、像素烧录文字检查、自由文本与私有标签审查、复核报告 | 重识别风险、像素 PHI、跨序列关联 |
| 合规 | 明确“仅供工程评审、不用于临床” | 由法务/合规与质量负责人评估个人信息保护、数据安全、网络安全、医疗器械软件和目标市场法规是否适用 | 适用性结论、风险管理、质量体系、验证确认 |
| 协作 | 单人本地流程；不做实时协同 | 乐观锁/版本号、冲突提示、评论与通知、任务归属；确有业务价值后再评估实时协作 | 覆盖写、结论版本、责任追踪 |
| 安全 | 文件类型/大小/路径校验设计，统一错误且不返回堆栈 | 威胁建模、依赖与镜像扫描、恶意文件隔离、速率限制、漏洞响应、渗透测试 | 上传攻击、路径穿越、拒绝服务、供应链 |
| 可用性 | 本地健康检查、结构化日志、SQLite/本地文件 | 高可用部署、PostgreSQL/对象存储、备份恢复演练、监控告警、容量和灾备目标 | RPO/RTO、数据一致性、故障演练 |

## 演示角色权限矩阵

该矩阵用于说明边界；P4/P5 不实现真实登录。

| 操作 | 规划工程师 | 技术评审员 | 只读用户 |
|---|:---:|:---:|:---:|
| 创建项目/脱敏病例 | 允许 | 禁止 | 禁止 |
| 关联和整理素材 | 允许 | 可补充标签/问题 | 禁止 |
| 查看白名单元数据/预览/模型 | 允许 | 允许 | 允许 |
| 提交评审结论 | 允许 | 允许 | 禁止 |
| 删除未评审素材 | 允许 | 禁止 | 禁止 |
| 删除已有评审历史的素材 | 禁止；软删除/归档尚未实现 | 禁止 | 禁止 |

所有授权判断在真实系统中必须由服务端执行，前端隐藏按钮不能作为权限控制。

## 审计与运行日志分界

- 运行日志回答“系统是否正常”：路由、状态码、耗时、错误码、request_id。
- 审计日志回答“谁对业务对象做了什么”：actor、object、action、result、before/after 摘要、occurred_at、request_id。
- 两类日志都不得写入 PatientName、PatientID、请求正文、完整 DICOM 标签集合或原始文件名。
- 上述审计事件是未来方案，当前只有评审历史与运行日志；实现时应采用追加式记录，更正通过新事件表达，不覆盖旧事件。

## 协作边界

MVP 不做多人实时协同。真实产品优先实现版本号和乐观锁：当用户基于旧版本保存时返回冲突，并允许刷新、比较后重新提交。只有在用户研究证明“同一病例需要多人同时编辑”后，才评估 WebSocket、在线状态或实时光标。

## 法规声明

本项目不宣称符合或获得任何医疗器械、个人信息保护或国际医疗数据法规认证。若进入真实机构或患者数据场景，必须先完成目标地区、部署形态、预期用途和数据流的适用性评估，再决定质量体系、注册、验证确认和安全控制要求。
