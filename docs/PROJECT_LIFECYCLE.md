# 项目生命周期与阶段门禁

本文件是项目流程的权威定义。每个阶段必须有证据，不能仅凭“已经做过”标记完成。

## P0 环境准备

目标：建立可重复、隔离、安全的开发环境。

退出条件：

- VS Code 可以打开固定项目根目录。
- Node、npm、Python、Git 版本已记录。
- 后端 `.venv` 和前端 `node_modules`/锁文件可用。
- 推荐扩展已安装或明确记录未安装原因。
- Git 仓库初始化，运行时数据与密钥已忽略。
- `scripts/verify-env.ps1` 运行并记录 Docker 等已知缺口。

## P1 产品设计

目标：从用户问题而不是技术清单定义产品。

退出条件：

- 一个首要用户、一个核心痛点和一个核心任务得到确认。
- 一句话定位、JTBD、主流程、异常流程和非目标明确。
- MVP 范围、PRD、验收矩阵、成功指标和五分钟演示脚本获确认。
- 开放问题有结论或明确默认值。

## P2 技术设计

目标：为已确认的产品范围选择最小可靠架构。

退出条件：

- 系统上下文、模块边界、数据模型和 API 约定完成。
- 文件存储、DICOM 解析、3D 查看、request ID、日志和错误模型明确。
- 隐私、安全、性能、迁移与部署取舍形成 ADR。
- 每项技术设计可以追溯到需求或非功能约束。

## P3 脚手架

目标：建立可运行但不承载业务复杂度的工程底座。

退出条件：

- React/Vite 与 FastAPI 空工程可启动。
- `/api/v1/health`、基础 request ID、日志和错误格式可验证。
- SQLite 初始迁移可从空库执行。
- lint、类型检查、单元测试和构建命令可运行。
- CI 或等价的统一检查入口存在。

## P4 后端

目标：实现核心数据、文件和评审服务。

退出条件：

- 项目/案例/素材/评审的数据与 API 完整。
- 文件校验、存储、哈希、DICOM 白名单元数据和预览可用。
- 核心后端验收项通过。

## P5 前端

目标：实现可完成核心任务的用户界面。

退出条件：

- 项目、案例、素材和评审主流程可操作。
- 图片/DICOM 预览和 STL 四项交互可用。
- 状态、加载、空态和错误反馈清楚。

## P6 异常/边界

目标：使失败可见、可记录、可恢复。

退出条件：

- 损坏、缺失、伪造格式、超限、无 Pixel Data、3D 加载失败和保存失败得到处理。
- 错误均有稳定错误码、request ID、用户下一步和测试证据。

## P7 运维化

目标：建立可部署、可观察和可排障的运行方式。

退出条件：

- Docker Compose、Nginx、环境配置和持久卷可用。
- 健康检查、结构化日志、备份/恢复和故障排查说明完成。
- PostgreSQL 切换路径得到验证或清楚说明限制。

## P8 测试

目标：用自动化和人工证据证明实现满足要求。

退出条件：

- 单元、集成、前端组件和 Playwright 主流程通过。
- 至少一条异常 E2E、隐私日志扫描和依赖安全检查通过。
- 测试报告包含环境、范围、结果和已知风险。

## P9 文档

目标：收口所有面向开发、运行、评审和交付的材料。

退出条件：

- README、PRD、技术设计、API、数据来源、测试、部署、排障和 AI 使用记录与实现一致。
- 所有命令在新环境复核。
- 演示脚本、截图/录屏和已知限制完成。

## P10 交付验收

目标：证明交付物可被第三方独立运行和评审。

退出条件：

- 新环境按 README 成功启动。
- 五分钟演示完整通过，刷新/重启后数据仍可追溯。
- 交付清单、许可证/来源、测试证据和风险说明完整。
- 最终范围与题目要求逐项对照，无未解释缺口。
