# 用户流程与范围

文档状态：Approved for P1  
更新时间：2026-09-20

## 主流程

1. 术前规划工程师创建项目。
2. 在项目下创建一个脱敏病例。
3. 把同一病例的 DICOM、图片和 3D 模型关联到病例下。
4. 系统识别素材类型、记录通用来源类别、计算哈希并检查是否可加载；逐素材来源与去标识化状态仍是待补的数据治理目标。
5. 用户浏览图片缩略图，按类型、状态或标签筛选，并选择两张图片并排比较。
6. 用户查看 DICOM 元数据/缩略图或 3D 模型。
7. 用户通过标签、状态、备注整理素材，并逐条填写评审结论。
8. 系统保存评审结论，后续重新打开仍可追溯。

## 评审结论字段

| 字段 | 说明 | 示例 |
|---|---|---|
| `status` | 当前评审状态 | 待评审、可用、需补充、不可用 |
| `conclusion_text` | 人工评审结论文本 | “LA 模型可加载，结构完整，可用于讨论前展示。” |
| `reviewer` | 评审人或演示角色 | 术前规划工程师 |
| `reviewed_at` | 评审时间 | UTC ISO 8601 |
| `issue_summary` | 问题摘要，可为空 | “DICOM 为多帧文件，需按帧预览。” |
| `next_action` | 下一步，可为空 | “补充 PNG 标注图。” |

## MVP 范围

### 必须

- 项目/病例/素材三级结构。
- 素材卡片/详情：格式、通用来源类别、标签、状态；备注在详情中编辑，逐素材来源/脱敏状态尚未实现。
- 状态流转和评审结论保存。
- 图片：缩略图浏览、按类型/状态/标签筛选、选择两张并排比较；通过标签、状态和备注完成整理。
- 3D 查看：旋转、缩放、平移、复位、结构标记。
- DICOM：安全元数据、缩略图、单文件预览；Rubo 样本按多帧单文件处理。
- 异常：缺失、格式不支持、加载失败、保存失败；来源不全是待补的数据治理约束，当前 API 未校验。
- 结构化日志带 `request_id`，不输出患者姓名、患者 ID、请求正文或原始文件名。

### 应该

- 结构标记点列表回看。

### 以后

- 更完整的 DICOM 序列浏览。
- PostgreSQL、对象存储和后台转换任务。
- 多人实时协同、版本历史和通知。
- 产品内 AI 评审摘要草稿；即使后续接入，也必须由人审阅、修改并确认后才能保存。

### 不做

- 临床阅片。
- 诊断结论。
- 治疗建议。
- 真实患者数据。
- 完整 PACS/阅片器。
- 自动分割、模型训练、空间配准和手术导航。
- AI 自动判定素材临床可用性、诊断结论或治疗建议。

## 异常流程

- 空文件或文件缺失：拒绝上传或返回稳定错误，不创建一条“不可用”素材。
- 扩展名与内容不一致：提示格式校验失败并记录原因。
- DICOM 无 Pixel Data：保留安全元数据，说明不能生成预览。
- 多帧 DICOM：按多帧单文件处理，不把目录误认为序列。
- STL 损坏或过大：展示加载失败或限制信息，不影响其他素材。
- 保存失败：保留未提交内容并允许重试，日志关联 `request_id`。

## 五分钟演示路径

1. 打开工作台，进入“结构性心脏病术前讨论 Demo 项目”。
2. 打开 seed 已创建的脱敏病例 `DEMO-TAVR-001`；若未 seed，则手动创建，避免同项目编号重复返回 409。
3. 在全新克隆中使用 seed 的合成 PNG、已脱敏的公开 CT DICOM 和已署名 CC BY 4.0 的心脏参考 STL；上传第二张合成 PNG。心脏模型不是该 CT 的病例重建。题目 STL 可按 README 另行准备，Rubo 96 帧样例不是默认交付素材。
4. 浏览并筛选图片，选择基线图与标注图并排比较，用标签、状态和备注整理。
5. 查看 CT DICOM 的安全元数据和缩略图；如另行取得 Rubo 样例，再验证多帧单文件。
6. 打开 3D 模型，完成旋转、缩放、平移、复位和结构标记。
7. 将素材状态分别标记为“可用”或“需补充”。
8. 保存评审结论，刷新页面后确认结论仍存在。
