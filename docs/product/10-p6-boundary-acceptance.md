# P6 异常与边界验收

状态：收口完成（2026-09-21）

P6 不新增业务主链路，只把 P4/P5 已有能力在失败时变成可见、可追踪、可恢复的行为。

## 验收结果

- [x] 伪造或损坏图片返回 `422 IMAGE_PARSE_FAILED`，响应包含 `request_id`，不落下半成品文件。
- [x] 超过配置上限的上传返回 `413 UPLOAD_TOO_LARGE`；上传读取至多累计上限加 1 字节，不会把超大文件一次性读入内存。
- [x] 经仓储 `_commit()` 的数据库提交失败返回 `500 PERSISTENCE_FAILED` 并回滚；当前删除路径直接提交不在此覆盖范围，文件与 DB 也未实现原子事务，见技术设计已知风险。
- [x] STL 加载失败由前端 Error Boundary 显示失败提示和“重试”，不永久停留在 loading。
- [x] 图片预览 404/加载失败显示可恢复的 fallback，不显示空白区域。
- [x] 异常响应沿用统一错误信封，并保留 `request_id`；访问日志记录完成状态和耗时。
- [x] `scripts/check.ps1`、API 单元测试、前端 lint/test/build、Playwright 主流程均通过。

## 面试边界

本阶段仍不引入真实 AI、临床诊断或治疗建议；错误恢复仅针对工程状态。所有素材评审结论仍由人工确认；默认演示使用仓库内合成 PNG、公开心脏参考 STL 与 seed 生成的非临床 DICOM phantom，另行取得的 DICOM 只用本地清理副本。
