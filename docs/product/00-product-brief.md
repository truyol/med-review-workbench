# 产品简介

文档状态：Approved for P1  
更新时间：2026-09-20

## 一句话定位

面向结构性心脏病术前规划工程师和影像技术评审员的素材评审工作台。

## 用户问题

TAVR 等结构性心脏病术前讨论前，同一病例的 CT/DICOM、标注图片和 3D 解剖模型常散落在网盘、本地目录或沟通记录中。素材是否可用、来源是否清楚、评审状态是什么、最终结论是谁在什么时候留下的，往往难以追溯。

这会导致讨论前反复找文件、验证链路靠人工记忆、问题不能沉淀，工程交付和方案讨论都缺少稳定依据。

## 产品目标

把同一病例的 DICOM、图片和 3D 模型聚合到一个病例上下文里，完成素材验证、状态标记和评审结论沉淀。

## 首要用户

术前规划工程师。

该角色负责在术前讨论前汇总病例素材、验证可用性、标记问题并准备可追溯的技术结论。

## 次要用户

影像技术评审员。

该角色负责复核素材质量、确认是否满足讨论或后续方案制作需要，并留下评审结论。

## 核心价值

- 素材可追溯（产品目标）：知道素材来自哪里、是什么类型、是否能加载、是否有问题。当前仅记录通用类别、类型和哈希；仓库样例在文档中登记来源，逐素材溯源字段待补。
- 结论可沉淀：可查看已评审素材的状态、备注、评审人和时间；未评审素材没有评审结论，备注当前允许为空。
- 边界可控：只做工程评审与素材准备，不做诊断、治疗建议或临床决策。

## 产品思维门禁

每个功能进入 MVP 前必须回答四个问题：

1. 先问为什么：解决谁的什么痛点？
2. 定义边界：做什么，不做什么？
3. 排优先级：是否属于主流程闭环？
4. 可验证：能否通过一个用户操作流程证明它有效？

不能回答这四点的功能不进入当前版本。

## 成功标准

- 用户可以在 5 分钟内完成一次病例素材评审演示。
- CT/DICOM、心脏结构 STL 和两张合成对照图片可以被归入同一病例。
- 图片可以浏览、筛选、并排比较，并通过标签、状态和备注完成整理。
- 每条素材都有格式、通用来源类别和状态；标签、备注、评审结论按用户操作产生，逐素材来源是尚未满足的产品目标。
- 已提交评审保存决定、可选备注、时间和评审人；必填文本结论仍是待补目标。
- 刷新或重启后评审结论仍可追溯。
- 日志、界面和 Git 中不输出真实患者敏感信息。

## 明确不做

- 不做临床诊断。
- 不做治疗建议。
- 不做完整阅片器。
- 不接真实患者数据。
- 不做自动分割、模型训练、空间配准或手术导航。
- MVP 不做多人实时协同、复杂权限或重型基础设施。
